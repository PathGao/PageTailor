# PageTailor Roadmap

产品一句话：读者决定网页长什么样。用预设或和 AI 对话改网页样式，按网址保存，下次自动套用。

## Doing

- **M1 预设：Google 搜索结果多列、Gemini 对话加宽。** 不接 AI。目的是最快发出第一版，验证宣发能带来多少用户；同时定下样式规则的存储格式（见 ARCHITECTURE.md「样式规则」），M2 的 AI 生成直接复用。2026-10-13 第一版可加载，等用户在 ego 里看效果。
- **苹果风外观预设：Google、Hacker News、维基百科。** 2026-10-13 用户要求"按 agent 的审美做一套苹果视觉感"，并"多动动老网站、提高图片占比、用上网站自己的颜色"。已做完，等用户看。Gemini 用户说视觉不错，不改。

## Planned

按大致顺序：

1. **更多预设：AI 对话页。** ChatGPT、Claude、DeepSeek 等窄栏对话页加宽。具体网站待用户定。
2. **中文网站预设。** 百度已做（见 Done）；其余中文网站待定。
2b. **自愈循环的上报部分。** 本地检查已做（见 Done）。把「哪个网站、哪个角色失效」匿名上报，由 AI 或人修适配后推送给所有用户。需要用户先定：上报到哪、怎么征得同意（默认关、首次询问）、隐私说明怎么写；还要服务端。
3. **M2 AI 对话改样式。** 侧边栏对话，多轮修改，满意后保存。用户自带 API key。模型只生成 CSS。
4. **M3 样式失效自动修复。** 网站改版导致保存的样式匹配不到元素时，用保存时记下的原始要求让 AI 重新生成。这是和 Dispel 等现有产品的主要差别，所以 M1 起每条规则都存原始要求。
5. **AI 标重点。** 模型读正文，挑出重点句并高亮。插件代码执行高亮，模型只返回位置数据。
6. **通用加宽按钮（待定）。** 没有预设的窄栏网站，点插件图标把正文撑宽。只加宽，不自动分列，不自动生效。用户尚未确认要不要做。
7. **网站偏好增强样式（2026-10-13 用户提出）。** 用户标记认可或不喜欢的网站，用来调整搜索结果的样式：认可的优先拉宽、显示更醒目，不喜欢的弱化或排后。Google 排名会被 SEO 操纵、只衡量相关度，用户认为不够可靠，所以「哪张卡片更重要」最终由网站偏好决定；在此之前按内容丰富度（配图、评分、价格、回答数）选，排名只做兜底。
8. **屏蔽垃圾站（2026-10-13 用户提出）。** 全是广告的站、诱导点击后不断跳转的站，从 Google 结果里屏蔽。现成方案 uBlacklist 已支持订阅社区维护的名单，做的话优先兼容它的名单格式，不自己从零攒名单。原本和工作区的清流项目重合，用户已决定删除清流，归 PageTailor。
   - 交互（用户定，2026-10-13）：接入判断模型或有屏蔽规则时，网页右下角/右侧悬浮一个垃圾桶球。刚打开搜索页等页面时，被屏蔽的条目化成粒子飞进垃圾桶。鼠标悬停在垃圾桶球上时展开，能看到被屏蔽的网页卡片。
9. **首次加载防闪。** 浏览器刚启动后第一次打开页面，读存储慢，实测样式比首次绘制晚 1ms（之后的页面早 40–200ms）。改法：background 用 `chrome.scripting.registerContentScripts` 按开关状态注册预设的 CSS 文件，浏览器在首帧前注入。
10. **CLA。** 建 GitHub 仓库时接入 CLA Assistant，在接受第一个外部 PR 之前完成。协议文本采用现成模板，不自行起草。
11. **商业化：闭源云服务。** 免 API key 直接用、多设备同步、样式分享库。插件本体保持 AGPL。
12. **翻译（远期，考虑中）。** 作为阅读层的一个功能，不作为主打。

## Not Do

- **生成 JS。** MV3 禁止插件执行远程生成的代码，模型生成的 JS 也算。只能走 `chrome.userScripts`，要求用户手动打开开关，门槛和审核风险都高。CSS 已覆盖改外观；标重点这类需要改内容的功能，由插件自己的代码执行，模型只返回数据。
- **fork Dispel。** 它只按域名存、不看截图、不检查效果、样式失效不修。这些都在核心路径上，改它的代码不比从零写省事。可以参考它的点选元素、外部资源警告等做法，复制代码时保留 MIT 版权声明。
- **全自动识别并修改所有网站。** 通用算法猜不准页面结构（class 名是乱码、动态加载、固定输入框），容易把页面改坏。改动必须由预设或用户触发。
- **用网站的大图（og:image）替换 Google 的小缩略图。** 要替用户去访问每个搜索结果网站，等于把搜索记录泄露给这些网站，还多出大量请求。Google 自带的缩略图只有 92px，苹果风预设填满 Google 留的位置为止。
- **Google 结果用瀑布流。** 2026-10-13 做过一版（4px 细行 + 按高度占行），用户用后否定：卡片位置参差让视线来回找，末尾留空。改为规整网格。
- **对话页分多列。** 对话要按顺序读，分列后视线来回跳。对话页只加宽。
- **以"沉浸式翻译上位替代"定位。** 它的壁垒是几千个网站的段落识别规则、PDF/字幕等场景和自带翻译服务，短期追不上。
- **政变类名字（Pagecoup、Overthrow 等）。** 在中文互联网难以传播。
- **Restyle、Pagelift 等名字。** Restyle 同名太多；最终选 PageTailor。
